## reasoning送信構造の「未確認」の意味

元のB03では、実providerとの会話継続・tool実行・回答を確認した。
それとは別に、同じprovider/modelへ過去のreasoning等のprivate stateを適切な形で再送すること、

stateを送らないことを、送信HTTPの構造で確認する計画だった。 Responses
noteの再送回数もこの構造確認に含まれていた。

観測proxyの証明書を配置binaryが受理せず、4 request開始がTLS接続で失敗し、upstreamへ到達していない。
直接接続で会話は確認できたが、上記の送信構造を実wireで観測できなかったので未確認と記載した。
reasoningが存在しない、送信していない、実装が壊れているという判定ではない。

## Go HTTP 400の原因調査probe

利用者の原因調査指示に基づき、既存`scripts/probe_provider_response.py`のhandlerを利用した。
配置binaryから独自provider名のlocalhost endpointへ送り、同じGo endpointへ転送して400の本文を取得。
これは別probeとしての一時的raw取得であり、productionの常設収集・診断仕様は変更していない。
Authorization/header credentialは保存しない。前回の観測proxyのTLS問題はこの方式では発生していない。

最初の1 request（GOP-BASE）はHTTP 400。応答は`error.type=MissingSessionID`で、
`x-opencode-session`がないため効率的にroutingできないと明示されていた。
bodyには`model=deepseek-v4.1-flash`、`reasoning_effort=high`、stream=true、
max_completion_tokens=65536、2 messages、12 toolsがあった。

取得したbodyを変更せず、同じ認証・User-Agent `Henji-Harness`・endpointで2 requestを比較した。
差は`x-opencode-session`の有無だけ。body SHA-256は両方とも
`f883f936cdafeb6e76309c0a9c3297eb80664237ebbd9cd189f028f31b8ab00f`。

| 比較               | 結果                                                    | 時間   |
| ------------------ | ------------------------------------------------------- | ------ |
| session headerなし | HTTP 400、MissingSessionID                              | 0.53秒 |
| session headerあり | HTTP 200、SSE、read tool call、finish_reason=tool_calls | 1.75秒 |

**原因はE2E実行者が作成した試験用provider overrideからheadersを落としたこと。**
通常configの宣言にはUser-Agentと`x-opencode-session: {sessionId}`が既にある。
前回B03とGo再現2回は不備のある宣言での試験であり、そのHTTP 400をGo／DeepSeek highの
製品不具合として扱わない。highを変える修正やproduction adapterの修正は不要だった。
[Go公式docs](https://opencode.ai/docs/go/#where-can-i-use-it)も会話ごとの安定したsession headerと
固有User-Agentを案内しており、応答・比較結果と整合する。

最後に通常configの宣言をそのまま別XDGへ複製し、配置binaryでGo／DeepSeek highのread一回を直接実行。
GOP-DIRECTは2 requestともHTTP 200、2 model step、read success、exit 0で、 final
`HENJI_GOP_DIRECT_1d9f6b71b0a9`がfile内容と完全一致した。 execution
`96fcd7f1-9ed6-4004-a918-57e4bbb0ba26`。 新規会話の基本経路は成立。元のprovider切替のreasoning
wire確認まで完了したという結果ではない。

今回の追加は配置binary baseline 1 request、body比較2 request、配置binary直接確認2 requestの計5。
Sonar追加なし。production source・実config・常用binaryは変更していない。
